Il server ha ricevuto le intestazioni della richiesta; il client deve inviare il corpo.
Cosa fare: Di norma invisibile. Rilevante solo quando usi «Expect: 100-continue».

Il server accetta di cambiare protocollo, ad esempio passando a WebSocket.
Cosa fare: Se un WebSocket non si apre, controlla le intestazioni Upgrade e Connection attraverso eventuali proxy.

WebDAV: il server ha accettato la richiesta e sta ancora lavorando.
Cosa fare: Raro; trattalo come «attendi».

Permette al browser di precaricare risorse mentre il server prepara la risposta finale.
Cosa fare: Usato con le intestazioni Link per pagine più veloci.
La richiesta è riuscita.
Cosa fare: Per GET il corpo contiene la risorsa; per POST il risultato dell'azione.

La richiesta è riuscita e ha creato una nuova risorsa.
Cosa fare: Cerca un'intestazione Location con l'URL della nuova risorsa.

La richiesta è stata accettata per l'elaborazione, ma il lavoro non è finito.
Cosa fare: Interroga l'URL di stato fornito dall'API.

La risposta è stata modificata da un proxy.
Cosa fare: Di solito innocuo.

Successo senza corpo della risposta.
Cosa fare: Tipico di DELETE e di PUT senza risultato. Non provare a interpretare JSON.

Successo; il client deve reimpostare il modulo o la vista.
Cosa fare: Raro.

Il server restituisce solo l'intervallo di byte richiesto.
Cosa fare: Usato per lo streaming video e i download riprendibili (intestazione Range).

Ci sono più risposte possibili.
Cosa fare: Raro; scegli uno dei link offerti.

La risorsa ha un nuovo URL permanente.
Cosa fare: Aggiorna link e segnalibri. I motori di ricerca trasferiscono il posizionamento al nuovo URL.
Reindirizzamento temporaneo a un altro URL.
Cosa fare: Continua a usare l'URL originale; i browser possono cambiare POST in GET.

Reindirizza a un altro URL con GET dopo un POST.
Cosa fare: Il classico schema post/redirect/get.

La versione in cache è ancora valida.
Cosa fare: Non è un errore: il browser usa la cache (ETag o Last-Modified coincidono).

Reindirizzamento temporaneo che mantiene il metodo HTTP.
Cosa fare: Come il 302, ma POST resta POST.

Reindirizzamento permanente che mantiene il metodo HTTP.
Cosa fare: Come il 301, ma POST resta POST.

Il server non può comprendere la richiesta a causa di un errore del client.
Cosa fare: Controlla la sintassi JSON, i campi obbligatori, la codifica dell'URL e la dimensione delle intestazioni.

È richiesta un'autenticazione, oppure è fallita.
Cosa fare: Invia credenziali valide o un token aggiornato. Controlla l'intestazione Authorization.

Riservato ai sistemi di pagamento.
Cosa fare: Alcune API lo usano quando manca un limite di piano o un pagamento.

Sei autenticato ma non hai il permesso di accedere a questo.
Cosa fare: Controlla permessi, elenchi di IP consentiti, CORS e regole del firewall (WAF).

La risorsa non esiste a questo URL.
Cosa fare: Controlla l'URL per refusi, barre finali e maiuscole/minuscole; la risorsa potrebbe essere stata rimossa.

Il metodo HTTP non è supportato per questo URL.
Cosa fare: Guarda l'intestazione Allow; potrebbe servirti POST al posto di GET.

Il server non può produrre una risposta che corrisponda alle intestazioni Accept.
Cosa fare: Allenta l'intestazione Accept.

Un proxy richiede l'autenticazione.
Cosa fare: Configura le credenziali del proxy.

Il server è andato in timeout in attesa della richiesta.
Cosa fare: Riprova; controlla le reti lente e i caricamenti pesanti.

La richiesta è in conflitto con lo stato attuale della risorsa.
Cosa fare: Tipico dei conflitti di modifica e delle voci duplicate. Aggiorna e riprova.

La risorsa è stata rimossa in modo permanente.
Cosa fare: Rimuovi i link; i motori di ricerca eliminano la pagina più in fretta che con un 404.

È richiesta un'intestazione Content-Length.
Cosa fare: Aggiungila oppure invia con un corpo che il client possa misurare.

Una condizione nelle intestazioni della richiesta non è soddisfatta (If-Match ecc.).
Cosa fare: La risorsa è cambiata; recupera la versione più recente.

Il corpo della richiesta è più grande di quanto il server consenta.
Cosa fare: Riduci il caricamento o alza client_max_body_size / il limite.

L'URL è più lungo di quanto il server accetti.
Cosa fare: Usa POST con un corpo invece di una lunga query string.

Il server non supporta il tipo di contenuto della richiesta.
Cosa fare: Imposta il Content-Type corretto, es. application/json.

L'intervallo di byte richiesto è fuori dalla risorsa.
Cosa fare: Controlla l'intestazione Range rispetto alla dimensione del file.

L'intestazione Expect non può essere soddisfatta.
Cosa fare: Rimuovi «Expect: 100-continue».

Pesce d'aprile della RFC 2324.
Cosa fare: Alcuni server lo usano per respingere i bot.

La richiesta è stata inviata a un server che non può rispondere.
Cosa fare: Tipico del riuso delle connessioni HTTP/2 con un host TLS sbagliato.

La sintassi è corretta ma il contenuto non ha superato la convalida.
Cosa fare: Leggi il corpo dell'errore per i messaggi a livello di campo.

La risorsa è bloccata (WebDAV).
Cosa fare: Attendi oppure sblocca.

Il server non elaborerà una richiesta che potrebbe essere ripetuta.
Cosa fare: Riprova dopo l'handshake.

Il client deve passare a un altro protocollo.
Cosa fare: Usa HTTPS o una versione HTTP più recente.

Il server richiede una richiesta condizionale.
Cosa fare: Aggiungi If-Match.

Sei soggetto a limitazione della frequenza.
Cosa fare: Rallenta e rispetta l'intestazione Retry-After; aggiungi un back-off esponenziale.

Le intestazioni (spesso i cookie) sono troppo grandi.
Cosa fare: Cancella i cookie o riduci la dimensione delle intestazioni.

Il contenuto è bloccato per motivi legali.
Cosa fare: Non risolvibile lato client.

Il server ha incontrato una condizione imprevista.
Cosa fare: Un bug o una configurazione errata sul server; controlla i log del server.

Il server non supporta la funzionalità richiesta.
Cosa fare: Il metodo o la funzione non è disponibile.

Un gateway o proxy ha ricevuto una risposta non valida dal server a monte.
Cosa fare: L'applicazione dietro il proxy è andata in crash o è irraggiungibile; controlla lo stato dell'upstream e i timeout.

Il server non è temporaneamente in grado di gestire la richiesta.
Cosa fare: Sovraccarico o manutenzione; riprova più tardi e rispetta Retry-After.

Il gateway non ha ricevuto una risposta in tempo dal server a monte.
Cosa fare: Aumenta i timeout del proxy o velocizza il backend.

La versione HTTP non è supportata.
Cosa fare: Usa HTTP/1.1.

Il server non può memorizzare la rappresentazione (WebDAV).
Cosa fare: Libera spazio su disco.

Il server ha rilevato un ciclo infinito (WebDAV).
Cosa fare: Controlla reindirizzamenti o link.

Devi autenticarti per accedere alla rete.
Cosa fare: Tipico dei captive portal (Wi-Fi degli hotel); apri un browser ed effettua l'accesso.
