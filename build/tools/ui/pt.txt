O servidor recebeu os cabeçalhos da requisição; o cliente deve enviar o corpo.
O que fazer: Normalmente invisível. Só é relevante quando você usa "Expect: 100-continue".

O servidor concorda em trocar de protocolo, por exemplo para WebSocket.
O que fazer: Se um WebSocket não abrir, verifique os cabeçalhos Upgrade e Connection em qualquer proxy.

WebDAV: o servidor aceitou a requisição e ainda está trabalhando nela.
O que fazer: Raro; trate como "aguarde".

Permite ao navegador pré-carregar recursos enquanto o servidor prepara a resposta final.
O que fazer: Usado com cabeçalhos Link para páginas mais rápidas.
A requisição foi bem-sucedida.
O que fazer: Em GET o corpo contém o recurso; em POST, o resultado da ação.

A requisição foi bem-sucedida e criou um novo recurso.
O que fazer: Procure um cabeçalho Location com a URL do novo recurso.

A requisição foi aceita para processamento, mas o trabalho não terminou.
O que fazer: Consulte a URL de status que a API fornece.

A resposta foi modificada por um proxy.
O que fazer: Geralmente inofensivo.

Sucesso sem corpo de resposta.
O que fazer: Típico de DELETE e de PUT sem resultado. Não tente analisar JSON.

Sucesso; o cliente deve redefinir o formulário ou a visualização.
O que fazer: Raro.

O servidor retorna apenas o intervalo de bytes solicitado.
O que fazer: Usado em streaming de vídeo e downloads retomáveis (cabeçalho Range).

Há várias respostas possíveis.
O que fazer: Raro; escolha um dos links oferecidos.

O recurso tem uma nova URL permanente.
O que fazer: Atualize links e favoritos. Os mecanismos de busca transferem o ranking para a nova URL.
Redirecionamento temporário para outra URL.
O que fazer: Continue usando a URL original; navegadores podem mudar POST para GET.

Redireciona para outra URL com GET depois de um POST.
O que fazer: O clássico padrão post/redirect/get.

A versão em cache ainda é válida.
O que fazer: Não é um erro: o navegador usa o cache (ETag ou Last-Modified coincidiram).

Redirecionamento temporário que mantém o método HTTP.
O que fazer: Como o 302, mas POST continua POST.

Redirecionamento permanente que mantém o método HTTP.
O que fazer: Como o 301, mas POST continua POST.

O servidor não consegue entender a requisição por causa de um erro do cliente.
O que fazer: Verifique a sintaxe do JSON, campos obrigatórios, codificação da URL e tamanho dos cabeçalhos.

Autenticação é necessária ou falhou.
O que fazer: Envie credenciais válidas ou um token novo. Verifique o cabeçalho Authorization.

Reservado para sistemas de pagamento.
O que fazer: Algumas APIs usam quando falta um limite de plano ou um pagamento.

Você está autenticado, mas não tem permissão para acessar isto.
O que fazer: Verifique permissões, listas de IPs permitidos, CORS e regras de firewall (WAF).

O recurso não existe nesta URL.
O que fazer: Verifique a URL (erros de digitação, barras finais, maiúsculas e minúsculas); o recurso pode ter sido removido.

O método HTTP não é aceito para esta URL.
O que fazer: Veja o cabeçalho Allow; talvez você precise de POST em vez de GET.

O servidor não consegue produzir uma resposta que corresponda aos cabeçalhos Accept.
O que fazer: Relaxe o cabeçalho Accept.

Um proxy exige autenticação.
O que fazer: Configure as credenciais do proxy.

O servidor esgotou o tempo de espera pela requisição.
O que fazer: Tente de novo; verifique redes lentas e uploads grandes.

A requisição entra em conflito com o estado atual do recurso.
O que fazer: Típico de conflitos de edição e entradas duplicadas. Atualize e tente de novo.

O recurso foi removido permanentemente.
O que fazer: Remova links; os mecanismos de busca descartam a página mais rápido do que com um 404.

Um cabeçalho Content-Length é necessário.
O que fazer: Adicione-o ou envie com um corpo que o cliente consiga medir.

Uma condição nos cabeçalhos da requisição falhou (If-Match etc.).
O que fazer: O recurso mudou; busque a versão mais recente.

O corpo da requisição é maior do que o servidor permite.
O que fazer: Reduza o upload ou aumente client_max_body_size / o limite.

A URL é maior do que o servidor aceita.
O que fazer: Use POST com corpo em vez de uma query string longa.

O servidor não aceita o tipo de conteúdo da requisição.
O que fazer: Defina o Content-Type correto, ex.: application/json.

O intervalo de bytes solicitado está fora do recurso.
O que fazer: Confira o cabeçalho Range com o tamanho do arquivo.

O cabeçalho Expect não pode ser atendido.
O que fazer: Remova "Expect: 100-continue".

Piada de 1º de abril da RFC 2324.
O que fazer: Alguns servidores usam para rejeitar bots.

A requisição foi enviada a um servidor que não pode respondê-la.
O que fazer: Típico da reutilização de conexão HTTP/2 com host TLS errado.

A sintaxe está certa, mas o conteúdo falhou na validação.
O que fazer: Leia o corpo do erro para mensagens por campo.

O recurso está bloqueado (WebDAV).
O que fazer: Espere ou desbloqueie.

O servidor não processará uma requisição que possa ser repetida.
O que fazer: Tente de novo depois do handshake.

O cliente deve mudar para outro protocolo.
O que fazer: Use HTTPS ou uma versão mais nova do HTTP.

O servidor exige uma requisição condicional.
O que fazer: Adicione If-Match.

Você está sendo limitado por taxa.
O que fazer: Diminua o ritmo e respeite o cabeçalho Retry-After; adicione recuo exponencial.

Os cabeçalhos (muitas vezes cookies) são grandes demais.
O que fazer: Limpe os cookies ou reduza o tamanho dos cabeçalhos.

O conteúdo está bloqueado por razões legais.
O que fazer: Não dá para corrigir no lado do cliente.

O servidor encontrou uma condição inesperada.
O que fazer: Um bug ou configuração errada no servidor; verifique os logs do servidor.

O servidor não oferece a funcionalidade solicitada.
O que fazer: O método ou recurso não está disponível.

Um gateway ou proxy recebeu uma resposta inválida do servidor upstream.
O que fazer: O aplicativo por trás do proxy travou ou está inacessível; verifique a saúde do upstream e os timeouts.

O servidor está temporariamente incapaz de tratar a requisição.
O que fazer: Sobrecarga ou manutenção; tente mais tarde e respeite o Retry-After.

O gateway não recebeu uma resposta a tempo do servidor upstream.
O que fazer: Aumente os timeouts do proxy ou acelere o backend.

A versão do HTTP não é aceita.
O que fazer: Use HTTP/1.1.

O servidor não consegue armazenar a representação (WebDAV).
O que fazer: Libere espaço em disco.

O servidor detectou um loop infinito (WebDAV).
O que fazer: Verifique redirecionamentos ou links.

O que fazer: Típico de portais cativos (Wi-Fi de hotel); abra um navegador e faça login.
