How HTML Entity Encoder & Decoder works

Show "<b>" as text on a web page, escape user input or decode &amp;eacute; in scraped text. Choose whether to escape only the five characters that matter in HTML (& < > " ') or also every non-ASCII character, as named entities (&eacute;) or as decimal or hexadecimal numbers (&#233;, &#xE9;).

Encoding always escapes & first, so existing entities are not corrupted, and then < > " and '. Named mode uses a table of about 120 common entities and falls back to numeric references for everything else (including emoji, which become one code point and not two surrogate halves). Decoding handles named, decimal and hex entities, rejects invalid code points (replaced by U+FFFD) and, like browsers, accepts a few legacy entities without semicolon. Escaping output is the main defence against cross-site scripting when text is inserted into HTML.

Frequently asked questions

Which characters must be escaped in HTML?

Always & and <. Inside attributes also the quote character used. > and the other quote are escaped for safety.

What is the difference between &#233; and &eacute;?

Both display é. The numeric form works for every character; names exist only for a defined set.
