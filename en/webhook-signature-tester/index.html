How Webhook Signature Tester (HMAC SHA-256) works

Paste the raw request body and the signing secret and see the signatures a sender would produce: GitHub's sha256= and legacy sha1=, Stripe's t=…,v1=…, Slack's v0=…, plain hex, Base64 (used by Shopify and others) and SHA-512. Paste the signature header you actually received and the tool tells you whether it matches one of them, which quickly shows if the problem is the secret, the body, the timestamp or the header format.

A webhook signature is an HMAC (keyed hash) of the exact bytes of the request body, sometimes prefixed by a timestamp: GitHub signs the body, Stripe signs "timestamp.body" and Slack "v0:timestamp:body". The calculation uses the Web Crypto API in your browser. The most common reason for "invalid signature" is that the body was parsed and re-serialised before verification: even a changed space or a missing final newline changes the HMAC, so always verify the raw body. Compare signatures with a constant-time function and check that the timestamp is recent to block replays. Use a test secret here; do not paste production secrets into any website.

How to use it

  1. Paste the raw body and the secret.

  2. Optionally enter the timestamp and the received signature.

  3. Compare the calculated signatures with the header you got.

Frequently asked questions

Why does my signature never match?

Usually the body was changed before hashing (parsed JSON, trimmed whitespace) or the wrong secret or header format is used.

Is it safe to paste my secret?

Calculation is local, but use test secrets only. Treat any secret typed into a web page as exposed.

Are my files uploaded?

No. The file is opened and processed by your own browser. You can check it yourself: open your browser's network tab while using the tool, or disconnect from the internet after the page has loaded.

Is this tool free?

Yes, completely. There is no sign-up, no paid tier and no watermark on your files.
